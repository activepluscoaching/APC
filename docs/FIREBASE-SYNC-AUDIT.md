# FIREBASE SYNC AUDIT — foundation only, not production-ready

1. **Existing sync problem:** Online legacy sync is intentionally paused. Local login is not Firebase authentication.
2. **Root cause:** `js/realtime-sync.js` uses anonymous Firebase authentication. Re-enabling the shared bridge would not provide per-user authorization. `js/record-sync.js` discards unknown state versions and uses fingerprint merge rather than record-version preconditions. Existing Functions provisioning is not integrated into the local login path. Audit is targeted, not an exhaustive review of every repository file.
3. **Files changed:** `.gitignore` now excludes global env/key/service-account files while preserving legitimate JSON. `js/admin.js` destructive reset replaced with a non-destructive explanation. Prior redesign/auth changes remain intact.
4. **Files created:** Seven `firebase-sync/*.js` boundary modules; `tools/security/scan-secrets.mjs`; `tests/firebase-sync-foundation.test.mjs`; this report.
5. **Firebase architecture:** Dependency-injected, UI-independent foundation. Queue scoped by tenant and UID, cross-tab lock required, status subscription, lifecycle triggers. No production transport or application wiring yet. Adapter requires atomic local-record/outbox commit implementation; does not supply one. Remote pull is explicitly unsupported, not falsely reported successful.
6. **Security changes:** Client validation rejects selected credential fields; this is defense-in-depth, NOT server authorization or a complete field allowlist. Actual verified Firebase identity, server field schemas, trusted tenant membership and role enforcement still required. Legacy containment retained. No exposed key used.
7. **LocalStorage protection:** New namespace only. Unknown queue schema/corrupt JSON throws without replacing original data. No legacy migration performed. Removed existing destructive reset implementation. Existing data and backups not rewritten.
8. **Sync queue:** Stable operation IDs, record IDs, principal, device, timestamps, baseVersion, payload, status and attempts. Acknowledged, conflicted, invalid and failed items retained. Same-record ordering; independent invalid records do not prevent processing other records. Application writes are NOT yet connected to this queue.
9. **Retry mechanism:** Persistent exponential backoff with jitter, capped at five minutes, no discard after retry count. Manual retry for failed entries; authentication errors pause. Cross-tab flush lock and single-flight processing required.
10. **Conflict handling:** Explicit SYNC_CONFLICT from transport; later same-record writes blocked. No silent overwrite. Authorized resolution UI and server transaction implementation remain missing. Updating through adapter currently means full record replacement, not partial patch; integration must respect that contract.
11. **Firebase Rules:** RTDB remains deny-all, not deployed. Existing Firestore role rules remain unchanged and need further validation/hardening (including unrestricted field shapes for financial writes). No claim of production least-privilege completion.
12. **Server-side secret configuration:** Existing Firebase Functions is the preferred backend. Use managed runtime identity where possible. If a private key is necessary, provision FIREBASE_PROJECT_ID, FIREBASE_CLIENT_EMAIL, FIREBASE_PRIVATE_KEY in trusted secret storage only, normalize escaped newlines server-side, and never log them. No new key provisioned, no rotation performed. Console/IAM access not established; owner must revoke the reported compromised key before production use. Do not send keys in chat. Firebase web configuration is public, not an Admin secret.
13. **Offline test:** Foundation unit test verifies offline queue does not send and resumes later. Earlier redesign browser tests are not evidence of integrated secure sync. Required new app-wide offline regression not executed.
14. **Online test:** Mock transport only, not live Firebase or emulator. Ten foundation tests passed. Subsequent combined foundation/containment run timed out at 60 seconds; not PASS.
15. **Network interruption test:** Simulated lost acknowledgement retained operation and backoff. No real network interruption test executed.
16. **Duplicate test:** Simulated duplicate acknowledgement uses same operation ID. No server idempotency proof. Concurrent same-engine calls tested; separate-tab browser concurrency not tested.
17. **App update test:** Recreated queue retained entries; unsupported schema retained raw data. No new service-worker/app-upgrade integration test. New foundation is not added to app boot or cache.
18. **Security scan:** Pattern scanner found zero matches across eligible workspace files and 252 reachable Git history blobs. Covers PEM private keys, service-account JSON, private-key JSON and selected GitHub token patterns. Excludes dependencies/.git/.cache/.two-device-run, symlinks and workspace files >=10 MB; not a complete secret audit. No separate production bundle/browser/deployed scan. GitHub secret-scanning API returned HTTP 403, Resource not accessible by integration. No history rewrite justified by current scan. User-reported credential exposure remains unresolved regardless of scan result.
19. **Remaining warnings:** Full backend, trusted account migration, durable atomic feature-store integration, role/field schemas, remote hydration, user-visible conflict resolution and all required live/emulator/browser validation remain outstanding. Existing backend bootstrap endpoint and Firestore financial rules need security review before deployment. No broad *.json ignore: it would hide legitimate rules/config/test changes without detecting credentials in other extensions.
20. **Final status:** PARTIAL / NOT DEPLOYED. Foundation added and tested in isolation. Secure online sync is NOT restored. Do not enable legacy bridge or deploy this as a completed migration.
